War Project 资源经济基线（2026-09-19 落地，同日修订为双资源）：node 产出分弹药 ammo 与燃料 fuel 两种，map 模块只存两个「60 秒产出量」（NBT ammo_per_minute / fuel_per_minute；旧的单值键 resource_per_minute 迁移为 ammo）；命令 /warproject node setresource <nodeId> <ammoPerMinute> <fuelPerMinute>，FTB 大地图右键菜单为 Set ammo output / Set fuel output（弹窗提交两项，未修改的一项回传原值）。resource 包以枚举 ResourceKind(ammo|fuel) 为主键，SavedData war_project_resources 每队存 {id, ammo, fuel}，按 Config.resourceSettleIntervalSeconds（默认 5s）分别结算 产出*经过秒数/60，只发给 node 归属且 TeamData 中仍存在的队伍（盟友不分成）；命令 /warproject resource set|add|take <team> <ammo|fuel> <amount>。game end 清空两队资源并把所有 node 重置 neutral，stop 只冻结增量与消耗。网络协议号 "3"（C→S SetNodeResourcePacket 携带 ammo+fuel）。

War_Project 常有多 agent 并行改动同一仓库：默认在自行执行 gradle 构建（./gradlew build）或把 jar 覆盖同步到 D:\mc\.minecraft\versions\totalwar\mods先检查是否有其他agent在工作，以免与其他 agent 的构建/部署冲突，若没有时照常构建并同步。本机 Gradle **daemon 模式会卡死**（daemon 日志停在 “The daemon has started executing the build” 后毫无输出，5-10 分钟无进展、CPU 停滞，杀进程重试仍复现）；改用 `.\gradlew.bat build --no-daemon --offline` 并在后台作业里用 `*>` 重定向到日志文件，约 40 秒即可 BUILD SUCCESSFUL。
