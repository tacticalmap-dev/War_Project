# War Project 顶部 HUD 变薄定稿与「附着件偏移」耦合约束

接在 `d663de64-877e-4a01-8da6-3703f6e450c2`（内核样式求值语义与元素定位原则）与 `72ed23f4-82d1-4b8e-a724-27d157712ce6`（融合连接处几何定稿）之后：2026-09-22 深夜的一轮「变薄 / 缩窄 / 左右对称 / 动画」迭代结果。

**本文取代 `72ed23f4` 的几何参数表**——那份记的是条高 22、岛高 18、补片 20×11、含 `#seam` 盖缝条的版本，参数已全部失效。其中四条教训仍然有效：相邻 SDF 形状必须重叠、不能相切；重叠必须配不透明色；不要用整张宽 SVG 当背景；Python 轮廓模拟验证法。内核语义（CSS 覆盖 inline style、`justify-content` 只实现 center、随动件用 CSS 常量定位）见 `d663de64`；渲染质量与陷阱清单见 `f4af89b7`。

仓库：`E:\mc_mod_dev\War_Project`（MC 1.20.1 / Forge）；部署：`D:\mc\.minecraft\versions\totalwar\mods\war_project-1.0.0.jar`。

## 1. 定稿几何（GUI 像素）

| 部件 | 规格 |
| --- | --- |
| `#hud` | 高 **30** = 条 14 + 岛 16 |
| 条 `#topbar` | 单个圆角矩形：高 **14**、`border-radius:7px`、`padding:0 8px`、`gap:6px`、背景 `#000000`；宽 = 屏宽×**0.54**（clamp 200–360、量化 4px）。**没有任何端盖元素** |
| 岛 `#island` | 高 **16**、`border-radius:7px`、`padding:0 8px`、`gap:3px`、背景 `#000000`；紧贴条底边（y=14） |
| 图标 | PNG 按 **12px 原始尺寸 1:1** 绘制，不得缩放（用户明令） |
| 补片 `#filletL/#filletR` | SVG 盒 **15×7**；`left/right:-15px`、`top:0`，即左补片到岛左边缘外 7px、右补片到岛右边缘外 7px |
| 占领环 | 星外半径 **14.5**、内 **10.5**（`viewBox="-4 -4 32 32"`） |
| 轨道 | 宽 = 条宽×**0.62**÷2；满进度时填充宽 = 轨道宽（零留白） |
| 分数框 | 两侧**等宽**（= max(两侧文字宽)），左框文字右对齐、右框文字左对齐 |
| CEF 表面 | `CefWebRenderer.TOPHUD_HEIGHT = 30`，**必须等于 `#hud` 高**，否则转移面板错位 |

补片 path（左，15×7，三次贝塞尔 kappa = 0.5523）：

```
M 0 0 C 3.87 0 7 3.13 7 7 L 8 7 C 8 3.69 10.69 1 14 1 L 14 0 Z
```

右补片为 `x → 15 − x` 镜像：`M 15 0 C 11.13 0 8 3.13 8 7 L 7 7 C 7 3.69 4.31 1 1 1 L 1 0 Z`。

几何关系：**凹弧半径必须等于岛圆角半径**——这是「凹弧起点落在条底边上」与「凹弧与岛圆角外切」同时成立的唯一解；内侧那条弧半径取「岛圆角 − 1」，使补片向岛内叠 1px（重叠而非相切，避免抗锯齿缝）。

## 2. 教训一：附着件的偏移 ≡ −(目标元素 padding + 圆角半径)

补片挂在岛上，其水平偏移由岛的 `padding` 与圆角半径共同决定。本轮把岛的 `padding` 从 12 压到 8、**却漏改补片偏移**（仍按 `-(7+12) = -19` 摆），补片整体外移 4px，凹弧切点落不到岛边缘上，两者之间裂开一条 4px 的缝，直到用户截图报「有缝，请贴合」才暴露。

**检查清单**：任何「附着在另一元素上的装饰件」，改动目标元素的 `padding` / `border-radius` / 尺寸后，必须同步核对该装饰件的 `left/right/top`。做法上把这条耦合写进 CSS 注释，别只留在脑子里。

## 3. 教训二：位图按原始像素 1:1 绘制

HUD 图标是 12px 的 PNG。缩到 10px 会走重采样、边缘发糊，用户明确要求「不要改图标大小」。推论：**岛高的下限 = 图标高 + 2×2 = 16**，再矮就只剩 1px 余量。

## 4. 教训三：左右对称 = 等宽容器 + 朝外侧对齐

`min-width` + 左对齐的分数文本会让两侧「文字→轨道」的视觉间距不等（左侧多出 `min-width − 文字宽` 的空白）。正确做法：两个分数框取同一宽度 `max(两侧文字宽)`，左框文字右对齐（`padding-left = 宽 − 文字宽`）、右框文字左对齐（`padding-left = 0`）——两侧间距才严格相等，星标也正好落在条的几何中心。另注：内核 `justify-content:center` 曾错误地位移**容器自身**（把整条推出居中位置），已改为位移子节点；内容的左右留白因此才对称。

## 5. 教训四：动画类名必须有对应规则，否则是死代码

视图里每次占领方变化都 `setClass("flash", true)` 并附带 200ms 计时器，但页面里**从来没有 `.flash` 规则**，星星从不闪。内核**无 keyframes**，动画只能由 `tick` 驱动 `transition`：`.flash { transform:scale(1.5); transition:150ms; }`。注意 `Css.parseTransform` 里 `scale` 走 `parseFloat`（**接受小数**），而 `translate` 走 `parsePx`（取整）。

## 6. 可调参数与下限

- 条再薄 → 12 高需把星降到 8、圆角降 6，视觉开始局促；
- 岛再矮 → 16 是下限（图标 12 + 上下各 2）；
- 岛更宽/更窄 → 调 `.island` 的 `padding` 与 `gap`，并**同时**按第 2 节改补片偏移；
- 条宽比 `BAR_WIDTH_RATIO` 取 0.54 的目的：让条左端（GUI ~110）不压左上角地图模组的小地图（约 95 GUI 宽）。

## 7. 验证手法

沿用 `72ed23f4` 的两条：Python/PIL 按同一组参数合成轮廓并逐行打印连通 run（可在不启动游戏的情况下看出越界、空洞、凹弧是否收敛到岛边缘）；以及对游戏截图做阈值取证，量出各元素的精确像素边界与两侧留白是否相等。
